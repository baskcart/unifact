One Fact. One Truth.

UniFact User Guide

UniFact is where your organization keeps trusted facts — policies, decisions, and knowledge that people and AI can rely on. This guide is for everyone: founders, operators, reviewers, and teammates — not only developers.

What UniFact is (in plain language)

Think of Git as the place teams keep code. UniFact is the place teams keep facts — short, clear statements of truth with history, ownership, and approval.

  • “Our return window is 30 days.”
  • “Employees receive 20 days of PTO.”
  • “Staging registry lives at staging.unifact.ai.”
Documents are where facts are written. UniFact is where facts are managed, reviewed, and shared.

How organizations work

UniFact is tenanted by organization. A registry has a name — for example Unifact.

  1. Owner creates the registry: uni init Unifact --person admin
  2. Others request to join: uni join Unifact --person alice
  3. Owner approves: uni approve Unifact --person alice --by admin
  4. Owner can pause: uni suspend Unifact --person alice --by admin (restore with approve).
  5. Each person gets one API key; approve/suspend control whether it works.
  6. People and AI assistants use that key to read published facts and propose new ones.
Creating a registry is about the organization name, not about cloning a Git repository. You may optionally paste a GitHub/GitLab URL only to suggest the org name and description (UniFact reads public metadata from the URL — it does not run Git).

Who this is for

Owners & admins

Create the org registry, approve who joins, suspend access when needed.

Teammates

Join the org, pull trusted facts, propose updates for review.

Reviewers / curators

Approve or reject proposed facts before they become published truth.

AI assistants

Read published facts and propose new ones — same rules as people.

The life of a fact

StageMeaning
WorkingDraft on your side — not ready for the group yet.
ProposedSubmitted for review on the shared registry.
ReviewA curator is evaluating it.
PublishedApproved truth — safe for people and AI to use.

Facts can later be superseded or retracted when the world changes.

Everyday actions

Create or join a registry

uni init Unifact --person admin
uni join Unifact --person alice
uni approve Unifact --person alice --by admin
uni registries
uni team Unifact

init is like starting a new org workspace. join asks to become a member; the owner must approve.

Check your connection

uni status

Shows whether you are linked to the shared registry and which person key is active. Also lists local working / proposed / published counts.

Add a local fact

uni add "I don't feel talking when there are more people talking"
uni add "Returns are free within 30 days" --key return_window

Creates a proposed fact. Local agents can use proposed + review + feedback + published. Production agents only use published.

Owner: publish or open for feedback

uni push
uni publish policy/feeling_talk
uni feedback policy/feeling_sleepy

On a shared registry, owner uni push lands in feedback; others land in review. Owner uni publish only publishes from review or feedback (two-step). Solo registries may publish from proposed directly.

Get the latest published facts

uni pull

Like refreshing from the source of truth. Only published facts come down.

Send your proposals

uni push
uni push policy
uni push policy/feeling_talk
uni push policy/feeling_*

Uploads matching draft/proposed facts for review — not an automatic publish. You can push a whole namespace, one fact path, or a key glob (* / ?).

Your personal key

uni key create --person yourname
uni key list

Keys are stored in UniFact. Owners manage access with uni approve / uni suspend (not day-to-day key toggles). For a shared host, use the key printed by the owner's uni approve (uni key create --person you --api-key …) — a local-only key will get 403 on push.

Inviting someone else

  1. They run uni join Unifact --person theirname (or uni join staging.unifact.ai/Unifact --person theirname for a remote host).
  2. You approve on that same host: uni approve Unifact --person theirname --by you.
  3. Share the printed key. They install it: uni key create --person theirname --api-key … --namespaces '*'.
  4. They use uni pull / uni push.
  5. To pause access: uni suspend Unifact --person theirname --by you. Restore with uni approve again (same secret).
Shared host (for example staging.unifact.ai) can host many org registries. Access is per organization and per person — not “everyone on the server sees everything.”

Optional: suggest org details from a Git URL

If your company already has a public GitHub or GitLab project, you can paste the URL to fill in suggested names — without installing Git and without reading UniFact facts. 

uni meta https://github.com/your-org/your-repo

UniFact reads public hosting metadata (org, repo name, description). That does not replace creating or joining a UniFact registry.

What UniFact is not

  • Not a replacement for your code repository
  • Not a chat history or “agent memory dump”
  • Not an unreviewed wiki — publication is intentional
