One Fact. One Truth.

UniFact User Guide

UniFact is where your organization keeps trusted facts — policies, decisions, and knowledge that people and AI can rely on. This guide is for everyone: founders, operators, reviewers, and teammates — not only developers.

What UniFact is (in plain language)

Think of Git as the place teams keep code. UniFact is the place teams keep facts — short, clear statements of truth with history, ownership, and approval.

  • “Our return window is 30 days.”
  • “Employees receive 20 days of PTO.”
  • “Staging registry lives at staging.unifact.ai.”
Documents are where facts are written. UniFact is where facts are managed, reviewed, and shared.

How organizations work

UniFact is tenanted by organization. A registry has a name — for example Unifact.

  1. First person creates the registry for the org and becomes the owner.
  2. Others join that registry (they do not create a second “Unifact”).
  3. Each person gets one API key that can be turned on or off.
  4. People and AI assistants use that key to read published facts and propose new ones.
Creating a registry is about the organization name, not about cloning a Git repository. You may optionally paste a GitHub/GitLab URL only to suggest the org name and description (UniFact reads public metadata from the URL — it does not run Git).

Who this is for

Owners & admins

Create the org registry, approve who joins, turn keys on/off.

Teammates

Join the org, pull trusted facts, propose updates for review.

Reviewers / curators

Approve or reject proposed facts before they become published truth.

AI assistants

Read published facts and propose new ones — same rules as people.

The life of a fact

StageMeaning
WorkingDraft on your side — not ready for the group yet.
ProposedSubmitted for review on the shared registry.
ReviewA curator is evaluating it.
PublishedApproved truth — safe for people and AI to use.

Facts can later be superseded or retracted when the world changes.

Everyday actions

Check your connection

uni status

Shows whether you are linked to the shared registry and which person key is active.

Get the latest published facts

uni pull

Like refreshing from the source of truth. Only published facts come down.

Send your proposals

uni push

Uploads your draft/proposed facts for review — not an automatic publish.

Your personal key

uni key create --person yourname
uni key list
uni key on  --person yourname
uni key off --person yourname

Keys are stored in UniFact (not in a password file on your desktop). Off means that person cannot use the registry until turned on again.

Inviting someone else

  1. They should join your org registry — not create a new registry with the same name.
  2. After approval, they receive (or create with approval) a person key.
  3. They run uni pull / uni push with their key enabled.
  4. If they leave or you need to pause access, turn their key off.
Shared host (for example staging.unifact.ai) can host many org registries. Access is per organization and per person — not “everyone on the server sees everything.”

Optional: suggest org details from a Git URL

If your company already has a public GitHub or GitLab project, you can paste the URL to fill in suggested names — without installing Git and without reading UniFact facts. 

uni meta https://github.com/your-org/your-repo

UniFact reads public hosting metadata (org, repo name, description). That does not replace creating or joining a UniFact registry.

What UniFact is not

  • Not a replacement for your code repository
  • Not a chat history or “agent memory dump”
  • Not an unreviewed wiki — publication is intentional
