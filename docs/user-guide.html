UniFact User Guide

UniFact keeps trusted facts for your organization — policies, decisions, and knowledge that people and AI can rely on. This is the short path to get started.

The idea

Git is where teams keep code. UniFact is where teams keep facts — short statements of truth with ownership and approval.

  • “Our return window is 30 days.”
  • “Employees receive 20 days of PTO.”
Each organization has its own registry and its own facts. You only see orgs you own or belong to.

Get on an org

uni use admin
uni init Unifact

uni use alice
uni join Unifact

uni use admin
uni approve Unifact alice
uni team Unifact

First person inits the org and becomes owner. Others join; the owner approves. Pause access later with uni suspend Unifact alice.

See where you are

uni whoami
uni status
uni facts
uni facts Unifact

status shows you and your orgs. facts lists that org’s facts (if you belong to more than one org, name it).

Add and share facts

StageMeaning
ProposedDraft / submitted — not production truth yet.
Feedback / reviewOpen for comments or waiting on the owner.
PublishedApproved truth — safe for people and AI.
 
uni add "Returns are free within 30 days"
uni facts
uni publish policy/return_window
uni push policy/return_window
uni pull

add creates a proposed fact. Owner publishes production truth, then push / pull sync with the shared host. Only published facts come down on pull.

From a document

uni extract ./policy.md --dry-run
uni extract ./policy.md
uni facts
uni publish policy/…

Turns bullets/statements into proposed facts only — never auto-published.

Invite someone

  1. They: uni use theirname then uni join Unifact (or uni join staging.unifact.ai/Unifact).
  2. You (owner): uni approve Unifact theirname — share the printed key if they work against a shared host.
  3. They: uni pull / uni push with that same key.
